## Decisiones y riesgos para el humano
- **Defecto en T08 (no corregido, fuera de alcance):** frases naturales de queja de trato como «quiero poner una queja del trato de un empleado» o «tengo una queja por el trato del vendedor» NO escalan por reglas. Sí escalan «El vendedor fue grosero» y «me quiero quejar del empleado». Con `fake` no hay segunda capa; con un LLM real el clasificador T15 (si está activado) probablemente lo cubre. El revisor propuso regex mínimas y casos que no deben escalar; hace falta que decidas si reabres T08.
- **Cifra sembrada:** T10 acepta como sustento las cifras del mensaje y de turnos previos del cliente («me prometieron 900») y el agente podría repetirlas sin fuente. Es el diseño documentado; conviene mencionarlo como limitación o exigir fuente para cifras de política.
- Las reglas y el clasificador solo evalúan el mensaje actual, no el historial.
- El LLM recibe el texto original (el enmascarado solo se usa en logs); el id `ORD-####` no se altera por el enmascarado, pero otros datos sí podrían. Cédulas, nombres y direcciones no se enmascaran (límite de T09).
- Para `manipulacion` el LLM redacta el escalamiento con el mensaje crudo y sin tools; lo protegen el prompt, T10 y la plantilla de respaldo.
- El borde externo del orquestador escala ante cualquier excepción (incluye bugs), a diferencia del clasificador que propaga errores de programación.
- Cambios colaterales justificados por T14 en `resiliencia.py`, `mensajes.py` (`validar_historial` rechaza assistant vacío sin tools), `dobles.py` y adaptadores.
- MENOR T16: `llm_demo._PEDIDO` sin límite de dígitos (`ORD-10011` se lee como `ORD-1001`) y solo consulta el primer pedido; con una clave de Anthropic inválida `resiliencia` imprime un traceback en stderr.
- MENOR T14: ids de tool duplicados solo los detecta `FakeLLM`; historial que termina en `user` produce dos `user` seguidos sin test.
- El entry point `tiendahogar-chat` requiere reinstalar con `pip install -e .`.
